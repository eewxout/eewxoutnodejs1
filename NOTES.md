# NOTES

## Почему на DELETE возвращается 204, а не 200?
Потому что после удаления сервер ничего не возвращает. 204 значит "всё получилось, ответа нет".

## Что будет с данными при перезапуске сервера и почему так работает массив в памяти?
Данные пропадут. Массив лежит в оперативной памяти, а при остановке сервера память очищается. При новом запуске массив пустой, и seed() заполняет его заново.

## Зачем нужен next(err) и что сломается, если его убрать?
next(err) передаёт ошибку в errorHandler, и тот отвечает клиенту нормальным сообщением. Без него ошибка не дойдёт до обработчика: запрос повиснет или придёт некрасивая страница с ошибкой.

## Как реализовано персональное правило?
Формат serialNumber проверяется регуляркой (файл validateItem.js):
```js
const SERIAL_REGEX = /^[A-Za-z]{2}-\d{4}$/;
if (typeof serialNumber !== 'string' || !SERIAL_REGEX.test(serialNumber)) {
  return 'serialNumber должен быть в формате XX-0000 (2 буквы, дефис, 4 цифры)';
}
```
Одинаковые serialNumber запрещены (файл itemService.js):
```js
const duplicate = parts.find(
  (p) => p.serialNumber === serialNumber && p.id !== exceptId
);
if (duplicate) throw httpError(400, 'Запчасть с таким serialNumber уже существует');
```

## Где приложение может упасть и как это обработано?
- Запчасти с таким id нет: сервис выдаёт ошибку 404.
- Неверные данные в теле запроса: валидация отвечает 400.
- Повторный serialNumber: ошибка 400.
- Такого маршрута нет: notFound отвечает 404.
- Любая другая неожиданная ошибка: errorHandler отвечает 500.
